Offline-First State & TanStack Query v5

TanStack Query AsyncStorage React 19

Mobile networks are inherently unpredictable. Devices frequently encounter edge-cell handoffs, underground subway dead-zones, and sudden packet loss. In modern React Native development, your application state architecture must treat the network as an asynchronous enhancement rather than a prerequisite for rendering.

TanStack Query v5 bridges this gap by decoupling network fetching from local memory cache management. With deterministic stale-while-revalidate cycles, fine-grained garbage collection (gcTime), and auto-paused queries during disconnected states, client UIs can render instantly from storage before cellular radios even begin negotiating TLS handshakes.

Key Architecture Principles

  • Zero Stale Flashes: Hydrate queries synchronously from persistent cache (AsyncStorage or MMKV) before firing background network requests.
  • Hermes GC Protection: Calibrate gcTime to 24 hours to prevent memory churn while preserving instant app-resume navigation.
  • Capped Exponential Backoff: Mandate jittered exponential retries with a strict attempt ceiling to protect backend gateways from thundering herds upon device reconnection.

Deterministic Query Implementation

When configuring custom domain hooks for mobile screens, wrap TanStack’s useQuery with domain-safe retry boundaries:

TypeScript 
export const useRoadmaps = () => {
  return useQuery({
    queryKey: ['roadmaps'],
    queryFn: fetchRoadmaps,
    staleTime: 1000 * 60 * 5, // 5 minutes
    retry: queryRetryPolicy,
  });
};

Best Practices for Mobile Fetching

1
Decouple Stale Time from Garbage Collection Keep staleTime short (e.g., 5 min) for active views, but maintain a high gcTime (24h) so offline screen transitions are latency-free.
2
Online Manager NetInfo Synchronization Bind TanStack’s onlineManager directly to NetInfo. When the device regains Wi-Fi or cellular service, stalled mutations and active queries flush automatically.
3
Optimistic Mutations with Rollback Snapshots Always snapshot current cache states inside onMutate. If the device disconnects before the API validates, you can roll back seamlessly without loss of user confidence.
